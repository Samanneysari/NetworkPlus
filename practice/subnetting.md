# کارگاه Subnetting از صفر

Subnetting با حفظ جدول حل نمی‌شود؛ باید رابطه بیت، Prefix و Block size را بفهمید. این فایل روش، مثال و ۴۰ تمرین دارد. پاسخ‌ها در [فایل جدا](subnetting-answers.md) است.

## چهار مفهوم پایه

IPv4 سی‌ودو بیت دارد. Prefix مانند `/24` می‌گوید ۲۴ بیت برای Network و ۸ بیت برای Host است. Mask همان بیت‌ها را ده‌دهی نشان می‌دهد.

| Prefix | Mask | آدرس کل | Host معمولی |
|---:|---|---:|---:|
| /8 | `255.0.0.0` | 16,777,216 | 16,777,214 |
| /16 | `255.255.0.0` | 65,536 | 65,534 |
| /20 | `255.255.240.0` | 4,096 | 4,094 |
| /22 | `255.255.252.0` | 1,024 | 1,022 |
| /24 | `255.255.255.0` | 256 | 254 |
| /25 | `255.255.255.128` | 128 | 126 |
| /26 | `255.255.255.192` | 64 | 62 |
| /27 | `255.255.255.224` | 32 | 30 |
| /28 | `255.255.255.240` | 16 | 14 |
| /29 | `255.255.255.248` | 8 | 6 |
| /30 | `255.255.255.252` | 4 | 2 |
| /31 | `255.255.255.254` | 2 | 2 در Point-to-point |
| /32 | `255.255.255.255` | 1 | یک Host route |

فرمول‌ها: اگر `h = 32 - prefix`، تعداد کل `2^h` و در Subnet معمولی Host قابل‌استفاده `2^h - 2` است. `/31` و `/32` استثناهای کاربردی‌اند.

## روش Block size

برای `198.51.100.173/28`:

1. Mask `/28` برابر `255.255.255.240` است.
2. Octet جالب ۲۴۰ است؛ Block size برابر `256 - 240 = 16`.
3. مرزها: ۰، ۱۶، ۳۲ ... ۱۶۰، ۱۷۶.
4. ۱۷۳ در بازه ۱۶۰–۱۷۵ است.
5. Network=`198.51.100.160`.
6. Broadcast یک واحد پیش از مرز بعدی: `198.51.100.175`.
7. Host range: `.161` تا `.174`؛ ۱۴ Host.

## وقتی Prefix از /24 کوچک‌تر است

`10.40.19.200/20`:

1. Mask=`255.255.240.0` و Octet جالب سوم است.
2. Block size=`256-240=16` در Octet سوم.
3. مرزها ۰، ۱۶، ۳۲ ...؛ عدد سوم ۱۹ در بلوک ۱۶–۳۱ است.
4. Network=`10.40.16.0`، Broadcast=`10.40.31.255`.
5. Host range=`10.40.16.1` تا `10.40.31.254`.

## انتخاب Prefix از روی تعداد Host

برای ۱۲۰ Host، کوچک‌ترین `h` که `2^h - 2 ≥ 120` است، ۷ است؛ ۱۲۶ Host و Prefix=`32-7=/25`. برای ۱۲۷ Host، `/25` کافی نیست و `/24` لازم می‌شود.

## VLSM مرحله‌ای

از `10.50.0.0/23` برای بخش‌های ۲۰۰، ۱۰۰، ۵۰ و ۲ Host:

1. بزرگ به کوچک: ۲۰۰→`/24`، ۱۰۰→`/25`، ۵۰→`/26`، ۲→`/30` یا `/31` اگر تجهیزات پشتیبان.
2. تخصیص: `10.50.0.0/24`، سپس `10.50.1.0/25`، سپس `10.50.1.128/26`، سپس `10.50.1.192/30`.
3. هر Network باید روی مرز Prefix خودش باشد و Overlap نکند.

## Summarization

چهار شبکه پیوسته `10.60.0.0/24` تا `10.60.3.0/24` را می‌توان `10.60.0.0/22` خلاصه کرد، چون تعداد شبکه‌ها توان ۲، پیوسته و مرز شروع مضرب ۴ در Octet سوم است. Summary اضافی نباید شبکه ناخواسته را شامل شود.

## روش کنترل جواب

Network باید همه بیت‌های Host صفر، Broadcast همه بیت‌های Host یک و Host میان آنها باشد. برای هر VLSM، شبکه بعدی بعد از Broadcast قبلی و روی مرز Prefix خودش شروع شود. جواب را با ابزار فقط **پس از محاسبه دستی** Verify کنید.
